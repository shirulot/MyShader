# MyShader

一个用于学习 Android OpenGL ES 2.0 与 GLSL ES 1.00 的小型项目。

项目把每个练习拆成独立的片元着色器文件，通过首页 RecyclerView 选择不同 Demo。目标是从纹理采样、颜色处理开始，逐步理解美白、肤色权重、邻域采样、边缘保护和双边滤波等基础。

## 运行方式

使用 Android Studio 打开项目后运行，或在项目根目录执行：

```bash
./gradlew :app:assembleDebug
```

设备需要支持 OpenGL ES 2.0。

## 使用方式

1. 首页按分组展示 Demo，组头默认收起。
2. 进入任意 Demo 后，可以切换“原练习图”“新的人像”和“双人图”。每次切换都会清除旧人脸状态并重新检测所选图片，快速切换时丢弃旧请求结果；当前 Shader 仍使用单脸参数，检测失败或返回非单脸数据时关闭人脸效果，避免混用关键点。
3. 基础组不显示滑条；美白组中 Demo 6–8、10 显示美白滑条，Demo 9 仅输出二值 mask、不显示滑条；Demo 11–13 使用固定采样权重、不显示滑条，Demo 14–17 只显示磨皮；Demo 18 不显示滑条，Demo 19–20 只显示磨皮，Demo 21–28 显示磨皮和暖色补正；Demo 29 显示暖色补正和饱和度，Demo 30–47 不显示滑条，Demo 48–49 只显示“黑眼圈”滑条，范围为 `0.00–0.15`；Demo 50–52 使用固定参数的局部 UV 形变，不显示滑条；Demo 53 只显示“大眼”滑条，范围为 `0.00–0.15`，默认值为 `0.00`，步长为 `0.005`；Demo 54–55 显示“大眼”和“瘦脸”滑条，大眼范围为 `0.00–0.15`、瘦脸范围为 `0.00–0.05`，默认值均为 `0.00`，步长均为 `0.005`；Demo 56–58 和当前 `main.frag` 只显示“口红”滑条，范围为 `0.00–0.50`，默认值为 `0.00`，步长为 `0.01`。所有滑条默认值均为 `0.00`；美白范围为 `0.00–0.15`，磨皮和暖色补正范围为 `0.00–1.00`，饱和度范围为 `0.00–0.30`。
4. 只有当参数既通过 SeekBar 传给对应 uniform，又在片元着色器的最终输出计算链路中实际使用时，才显示对应滑条；仅声明 uniform 或仅上传但未参与最终输出时，画面保持不变且不显示滑条。
5. 底部控制面板可收起；收起时面板下滑且测试图片不再被遮挡，点击底部“展开”后面板上滑恢复。
6. 控件是否显示按 Shader 的最终输出判断，而不是只看 uniform 声明；例如 Demo 18 虽声明 `blurStrength`，但最终输出未使用磨皮结果，所以不显示。Demo 29 的“暖色补正”和“饱和度”滑条分别上传 `warmthStrength`、`saturationStrength`，范围为 `0.00–1.00` 和 `0.00–0.30`。

## 人脸检测接入

- 使用 `com.google.mediapipe:tasks-vision:1.0.0`，图片模式、默认 CPU 推理，上限 6 张脸；每张脸独立保存 478 个点的归一化 x/y，暂不使用 z。上限不是检出率或实时性能保证。
- `MediaPipeFaceDetector.kt` 负责模型和图片资源，`FaceAnalysis.kt` 负责眼睛、嘴唇、轮廓的语义映射。画面左眼对应点 33/133 的中点，右眼对应 362/263 的中点；不使用随视线移动的虹膜中心。
- 检测结果中的每张脸独立保存。当前只允许恰好一张有效脸启用美型；无人、多脸、异常坐标、检测失败或正在切图时关闭人脸效果。未实现多人同时美型或跨帧身份追踪。
- 不修改已有 Shader 形变公式；新 SDK 点位并非 Mars 111 点的一一对应，影响范围和强度需要重新看图校准。
- 模型位于 `app/src/main/assets/models/face_landmarker.task`，为官方 float16/version 1；来源和 SHA-256 记录在 `app/src/main/assets/licenses/MediaPipe.txt`。模型随包，无需运行时下载。
- 练习页提供“开源许可”入口，离线显示来源、Apache-2.0 全文及 SDK 原始第三方 NOTICE。升级 SDK/模型时应同步核对声明；这不替代应用发布所需的完整隐私和依赖合规检查。
- 原 `app/libs/gpupixel-release.aar` 文件保留，但已移出依赖，不再加载 Mars。以后接 GPUPixel 渲染框架时可独立恢复，不必更换当前检测数据结构。

验证方式：Run 后依次切换两张单人图、双人图和张嘴图，再切回单人图。查看 `FaceAnalysis` 日志中的 `faceCount` 和 `pointCounts`；预期单人图为 `1 / [478]`，双人图为 `2 / [478, 478]` 且关闭美型，张嘴图用于观察内嘴轮廓是否从口红区域中扣除。仍需以设备实测为准，不能把配置上限当成真实检出人数。

2026-09-21 验证：Debug 构建、单元测试通过；PJZ110 真机检测测试依次返回 `1 / [478]`、`1 / [478]`、`2 / [478, 478]`、`1 / [478]`，单脸准入判断通过。六脸检出率、实时性能及形变视觉校准尚未验证。

## 目录说明

```text
app/src/main/assets/main.frag   # 当前练习中的主片元 Shader
app/src/main/assets/main.vert   # 共用主顶点 Shader
app/src/main/assets/shaders/    # 文件按效果主题存放；首页按课程章节归组
app/src/main/java/.../          # Android 页面、列表与 OpenGL 渲染器
app/src/main/res/drawable-nodpi # 两张本地测试人像
```

`main.frag` 是持续编写新练习的工作文件。需要归档时，以其中的 `void main()` 为主体，只保留 `main()` 实际引用或调用的声明、常量、函数及其注释，放入对应分类目录，再在 `ShaderDemoCatalog` 中添加首页条目。

## 渲染链路

`MainActivity` 选择 Demo → `ShaderDemoActivity` 创建 `ShaderSurfaceView` → `ShaderRenderer` 编译 Shader、上传图片纹理并调用 `glDrawArrays(GL_TRIANGLE_STRIP, 0, 4)` → GPU 执行片元着色器。
